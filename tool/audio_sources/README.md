# Move sound source

`wood-piece-placement.wav` is a decoded excerpt of **Board Game Pieces.WAV**
by **taure**, published on Freesound on January 24, 2021.

- Source page: https://freesound.org/people/taure/sounds/555190/
- License: **CC0 1.0 Universal**, https://creativecommons.org/publicdomain/zero/1.0/
- License verified on the source page on September 15, 2026.
- Author's description: "Sound of wooden board game pieces rattling inside a
  box, then being set and moved across the board. Some clicks as they are set
  down, some being slid across the board".
- Download used: https://cdn.freesound.org/previews/555/555190_2940947-hq.mp3
  (the publicly available high-quality MP3 preview, not the original WAV).

The source documents wooden board-game pieces, not a specific checker set.
Crown uses one isolated placement from this real recording for its wood-on-wood
landing sound. The quieter isolated impacts around 54.39 and 56.39 seconds and
the stronger impact around 87.11 seconds were inspected for onset isolation and
decay. The first has little preceding noise and a short, clean tail. Final tone
and loudness selection still benefits from listening on the target device.

## Recreating the checked-in excerpt

The excerpt contains 350 ms beginning at **54.320 seconds**. It is downmixed to
mono, decoded at 44.1 kHz / signed 16-bit PCM, and otherwise unprocessed.
It was extracted with FFmpeg 8.1:

- Download SHA-256: `4de39768ccf07f5d34bb2b1f7ce73a544cfdf39a56edfa96077f26fe15781105`
- Excerpt SHA-256: `b1cb3b43dba3e7244f41c80cc4e9b7cf533627d6dfe9e1d7bc63b1414149aaef`

```sh
curl -fL https://cdn.freesound.org/previews/555/555190_2940947-hq.mp3 -o /tmp/board-game-pieces.mp3
ffmpeg -i /tmp/board-game-pieces.mp3 -ss 54.320 -t 0.350 \
  -ac 1 -ar 44100 -c:a pcm_s16le -map_metadata -1 \
  tool/audio_sources/wood-piece-placement.wav
```

The small PCM excerpt is kept in the repository so normal regeneration is
offline and does not depend on a website or MP3 decoder version. Only the
processed `assets/move.wav` is bundled in the app.

## Preparing the runtime asset

From the repository root, run:

```sh
python3 tool/generate_move_audio.py
python3 tool/generate_move_audio.py --check
python3 -B -m unittest discover -s test/tool -p '*_test.py'
```

### Version B: fuller wooden body

The script verifies the source checksum, removes low-frequency rumble with a
60 Hz high-pass filter, and gently softens the top end with a 5 kHz low-pass
filter. The contact onset is detected on that cleanup-filtered signal, before
EQ or compression, preserving the original crop and 1 ms of pre-roll.

It processes the full excerpt with pre-roll in this order:

1. Existing cleanup filters.
2. Broad peaking EQ (RBJ biquad): **+2 dB at 400 Hz, Q 0.7**.
3. Soft-knee peak compression: **2:1 ratio, 0.5 ms attack, 65 ms release,
   6 dB knee**. Attack/release smooth the gain-reduction envelope in dB.
4. The original **140 ms** crop, with a **0.5 ms entry fade** and **12 ms exit fade**.
5. Match the baseline's RMS over the complete crop, then attenuate if needed to
   stay below the **0.65 full-scale peak ceiling**. No clipping or hard limiting.

The threshold is calibrated deterministically by 32 bisection steps to achieve
**2.5 dB maximum actual gain reduction** within the selected crop. With the
checked-in source, it is approximately **-26.263 dBFS**. It is measured on the
cleanup/EQ signal before final output gain, rather than on the normalized WAV.

The initial 4 ms attack was measured as too slow for this recording's very short
contact peak: matching RMS exceeded the peak ceiling, requiring about 0.50 dB
attenuation. A 0.5 ms attack catches enough of the transient to satisfy both
headroom and RMS matching. This adjustment is signal-based; subjective tone
still needs listening on the target device.

Measured output before 16-bit quantization:

| Measurement | Version B |
| --- | --- |
| Peak | -3.89 dBFS |
| RMS over 140 ms | -25.87 dBFS |
| RMS difference from baseline | approximately 0.00 dB |
| Maximum compression gain reduction | 2.50 dB |

There is no pitch shifting, artificial tone, added reverb, or randomization.
The output is mono 44.1 kHz, 16-bit PCM WAV. The processor uses only Python's
standard library; `--check` verifies both the runtime asset and the baseline
byte-for-byte. Signal tests exercise the EQ response, compression ratio,
attack/release, soft knee, headroom, loudness, and reference preservation.

### Comparing with Version A

`move-baseline.wav` is the previous runtime asset, preserved byte-for-byte as a
development-only comparison. Its SHA-256 is
`a39d8e98b3d56b3f9fe2df14b3a9e9712d7f5dbabdea40a61fb80a9789619be2`.
It is regenerated by the original cleanup, crop, fade, and peak-normalization
recipe. It is not included in the Flutter asset bundle.

On macOS, listen at the same system volume:

```sh
afplay tool/audio_sources/move-baseline.wav
afplay assets/move.wav
```

Also compare ordinary moves and multi-jumps on phone speakers and headphones.
The target is a fuller wooden contact with clear separation between jumps,
without boominess, pumping, or noticeable background noise. RMS matching is a
starting point for this comparison, not a guarantee of equal perceived loudness.
